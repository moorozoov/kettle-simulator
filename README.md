# Kettle Simulator

Небольшой 3D-симулятор на Godot 4.7: чайник можно взять, наполнить водой,
поставить на плиту, нагреть, перегреть и сжечь. Вода из переполненного чайника
или оставленного открытым крана образует лужи и постепенно затапливает комнату.

Текущая версия: **0.0.1**.

## Запуск

1. Установите Godot 4.7 или совместимую более новую версию Godot 4.
2. Импортируйте папку проекта по файлу `project.godot`.
3. Дождитесь завершения импорта текстур.
4. Запустите главную сцену клавишей `F6`/`F5`.

## Управление

- движение камеры — мышь;
- взаимодействие — `E`.

## Структура

- `scenes/` — игровые сцены и локальные скрипты окружения;
- `scripts/interactions/` — логика чайника и плиты;
- `scripts/systems/` — общие игровые системы;
- `assets/materials/` — PBR-, простые и водные материалы;
- `LICENSES.md` — источники и лицензии сторонних материалов.

## Работа с Git

Основная ветка — `main`. Новая работа выполняется в коротких ветках:

- `feature/<name>` — новая механика;
- `fix/<name>` — исправление;
- `chore/<name>` — инфраструктура и обслуживание.

Формат коммитов: `тип: краткое действие`, например
`feat: add room flood level` или `fix: connect kettle overflow signal`.

Правила выпуска версий описаны в [`docs/VERSIONING.md`](docs/VERSIONING.md),
а история изменений — в [`CHANGELOG.md`](CHANGELOG.md).

## Работа с агентами Codex

Правила проекта и распределение ролей находятся в `AGENTS.md`. Для сложной
задачи можно написать: «Реализуй задачу командой агентов: разработчик, QA и
ревьюер». Codex последовательно выполнит разработку, независимую проверку и
ревью, подготовит PR и оставит слияние на подтверждение пользователя.

Для продуктовой работы можно написать: «Продакт, предложи три следующие фичи»
или «Подготовь подробное описание этой механики на ревью». Продакт не передаёт
фичу разработчику, пока пользователь явно не одобрит полное описание.

Для управления работой: «Проджект, проверь сроки, блокеры и соблюдение плана».
Для визуальных ассетов: «Дизайнер, подбери лицензированные материалы для
одобренной фичи и принеси варианты на ревью».

Повторяемые процессы описаны в `.agents/skills/`. Локальная проверка проекта:

```bash
bash scripts/check_project.sh
```

Та же проверка автоматически запускается в GitHub для веток и pull request.

## Материалы

- `pbr/kitchen_wood/kitchen_wood.tres` — столешница;
- `pbr/interior_tiles/interior_tiles.tres` — пол;
- `pbr/painted_plaster/painted_plaster.tres` — стены;
- `simple/stainless_steel/stainless_steel.tres` — мойка, кран и металл;
- `simple/black_metal/black_metal.tres` — плита;
- `simple/black_plastic/black_plastic.tres` — ручки;
- `water/water_universal.tres` — общий материал воды.

Не назначайте общий `black_metal.tres` конфорке и общий металлический материал
корпусу чайника: их параметры меняются игровыми скриптами.
