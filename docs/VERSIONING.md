# Версионирование и выпуски

Проект использует Semantic Versioning: `MAJOR.MINOR.PATCH`.

Пока игра находится на ранней стадии, основной номер остаётся `0`:

- `0.0.PATCH` — небольшие исправления и промежуточные рабочие сборки;
- `0.MINOR.0` — заметный игровой этап или связанный набор механик;
- `1.0.0` — первая цельная публичная версия игры.

## Источник версии

Одинаковый номер хранится в двух местах:

- `VERSION` — удобен для скриптов и сборок;
- `project.godot`, параметр `application/config/version` — доступен Godot.

При выпуске оба значения меняются одним коммитом.

## Процесс выпуска

1. Убедиться, что ветка `main` запускается без ошибок.
2. Перенести готовые пункты из `Unreleased` в новый раздел `CHANGELOG.md`.
3. Обновить `VERSION` и `application/config/version`.
4. Создать коммит `chore: release X.Y.Z`.
5. Создать аннотированный тег `vX.Y.Z`.
6. Отправить ветку и тег в удалённый репозиторий.

Пример:

```bash
git tag -a v0.1.0 -m "Kettle Simulator 0.1.0"
git push origin main --follow-tags
```

## Ветки и коммиты

Ветки создаются от актуальной `main` и после проверки вливаются обратно.
Рекомендуемые префиксы коммитов:

- `feat:` — новая возможность;
- `fix:` — исправление ошибки;
- `refactor:` — изменение кода без изменения поведения;
- `docs:` — документация;
- `chore:` — настройка проекта, зависимости и релизы.

Крупные исходные бинарные файлы стоит переводить в Git LFS, когда они начнут
заметно раздувать историю. Текущие 1K-текстуры можно хранить в обычном Git.
